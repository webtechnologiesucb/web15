1 · HttpClient + interceptor

Registramos provideHttpClient(withFetch(), withInterceptors([swapiInterceptor])). Los componentes y servicios escriben rutas relativas y el interceptor las reescribe contra la base configurada; si esa base falla, reintenta con los mirrors.

2 · httpResource: tres estados con signals

httpResource convierte una petición HTTP en un recurso reactivo. La URL se calcula dentro de una función, así que cambiar id() relanza la petición automáticamente y cancela la anterior.

3 · Estados: loading / success / error

Siempre manejamos los tres estados. El interceptor también gestiona reintentos con mirrors en caso de fallo de red; un 404, en cambio, es definitivo y se muestra tal cual.

4 · Medir la recarga

Podemos medir cuánto tarda una recarga manual sin envolver el recurso: guardamos el instante de inicio y un effect() observa cuándo deja de estar cargando.
