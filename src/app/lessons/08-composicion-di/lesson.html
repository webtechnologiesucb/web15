1 · Composición con ng-content y slots

Un componente no tiene por qué conocer el contenido que muestra: <ng-content> deja huecos y select decide qué elemento va en cada uno. La tarjeta de la demo tiene cuatro zonas: icono, acciones, cuerpo y pie.

Tono de la directiva: @for (option of tones; track option) { }
@if (showIcon()) { ✦ } slot de acciones

Este párrafo es contenido por defecto: no lleva ningún atributo de slot, así que cae en el <ng-content /> sin select.

El icono lleva la directiva appHighlight. La tarjeta la encuentra con contentChild() y lo muestra en la cabecera.

Al quitar el icono, contentChild() pasa a undefined y la tarjeta deja de mostrar el aviso: la consulta es reactiva.

2 · Directiva de atributo y host bindings

Una directiva de atributo decora el elemento que la usa. Los host bindings escriben clases, estilos y atributos en ese elemento sin crear un wrapper.

Este párrafo usa appHighlight="{{ tone() }}".

3 · Directiva estructural (reto)

Una directiva estructural recibe un TemplateRef y decide cuántas veces lo inserta en un ViewContainerRef. El asterisco del uso es azúcar de Angular.

@for (count of [1, 3, 5]; track count) { }
  • Elemento repetido #{{ i + 1 }}

4 · providers por componente

La configuración de SWAPI es un InjectionToken con provider root. Un componente puede declarar otro provider y crear un ámbito propio: sus hijos verán el valor local, el resto de la aplicación seguirá viendo el root.

    @for (base of rootBases; track base) {
  • {{ base }}
    • }

5 · Estilos encapsulados

Los styles de un componente se encapsulan por defecto (ViewEncapsulation.Emulated): Angular añade atributos únicos para que .composed-card no se escape del componente.
